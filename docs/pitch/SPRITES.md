# Набор спрайтов и замена графики

Активный набор — 35 локальных PNG с прозрачностью: 20 домов (10 ступеней × A/B),
4 состояния парковок, 3 постоянных центра и 8 элементов окружения.
Исходники/экспорт: src/frontend/public/sprites/. Каталог: `http://localhost:5188/sprites/catalog.html`.

## Дома и прогрессия

Активные исходники находятся в source/house/; имена сохраняются буквально, включая суффиксы моделей.
XX — этажность концепта, а не порядковый номер ступени. Полное соответствие:

| Ступень | Накопленный XP | Этажность концепта | Файлы A/B |
| --- | --- | --- | --- |
| 1 | 0 | 1 | IC_L01_A.svg / IC_L01_B.svg |
| 2 | 11 | 3 | IC_L03_A.svg / IC_L03_B.svg |
| 3 | 22 | 4 | IC_L04_A.svg / IC_L04_B.svg |
| 4 | 33 | 5 | IC_L05_A_II05.svg / IC_L05_B_Brick.svg |
| 5 | 44 | 6 | IC_L06_A.svg / IC_L06_B.svg |
| 6 | 56 | 9 | IC_L09_A.svg / IC_L09_B.svg |
| 7 | 67 | 12 | IC_L12_A_P42_P43.svg / IC_L12_B_P44M.svg |
| 8 | 78 | 14 | IC_L14_A_P55.svg / IC_L14_B_Erker.svg |
| 9 | 89 | 17 | IC_L17_A_Section.svg / IC_L17_B_KOPE.svg |
| 10 | 100 | 25 | IC_L25_A_KOPE_Tower.svg / IC_L25_B_Stalin_Skyscraper.svg |

Пороги — round(i × 100 / 9), i=0..9: девять почти равных переходов через 11–12 XP.
Вместимость дома остаётся 100 XP; избыток по прежним правилам превращается в парковки.
Сохранённый XP не перераспределяется: новый уровень/этажность вычисляются из него.
Правила и API обновляются вместе с фронтендом. `rulesVersion` отделяет смену правил
от версии сохранённого мира и инвалидирует старую клиентскую проекцию без сброса БД.

Логические ID: house-01-a / house-01-b … house-10-a / house-10-b.
A/B выбирается детерминированным хешем постоянного ID дома, не случайным числом при рисовании.
Один дом сохраняет вариант в городской миниатюре, на улице, после перезагрузки и смены ступени.
Числовые XP/ступени на игровой экран не добавляются.

Оригинальные SVG не переименовываются и не перезаписываются. Их авторская metadata
README/manifest описывает лишь часть и предыдущую версию комплекта: спецификация использует все 20 реальных файлов.
Прежние source/new и source/old — архивы, не активные дома.
Текущий набор: два векторных одноэтажных дома 1120×1000 (pixelRatio=2)
и 18 SVG со встроенным PNG на индивидуальных холстах до 1560 px (pixelRatio=1).
Размеры берутся из фактического viewBox. Опоры измерены по прозрачности новых
изображений; изотропный масштаб сохраняет ширину домов около 94–122 world px.
При этой замене 15 спрайтов парковок, центров и окружения остаются побайтно прежними.
Как отмечено в авторском README, это не семантические редактируемые этажи: количество
нарисованных окон не является проверкой игровой этажности. Растягивать широкие корпуса
до высоты прежних башен нельзя: точки опоры и масштаб должны сохранять попадание в участок.

## Парковки

Активные исходники: source/parking/parking-01.svg … parking-04.svg. Текущие четыре
пользовательских SVG содержат встроенный PNG: первый 1672×941, остальные 1680×1030.
Экспорт выполняется в исходном разрешении (pixelRatio=1), без изменения оригиналов.
Прежние логические ID и правила сохранены: 01 = 1–3 места, 02 = 4–6, 03 = 7–9,
04 = 10 мест. При нуле объект исчезает; вместимость парковочного объекта остаётся 10.
Опоры на центре площадки: (840, 570) для 01 и (840, 635) для 02–04;
не на нижней точке тени. Индивидуальный изотропный масштаб даёт ширину около
135 world px внутри участка. 31 остальной спрайт, включая все дома, не меняется.
Проверка файлов и экспорта завершена; проверка текущего набора на игровом стенде
остаётся открытой, пока Docker Desktop не восстановлен после заполнения диска C:.

При наличии параллельных пользовательских правок экспорт/сборку выполнять в отдельном
снимке git archive HEAD с наложением только согласованных входов и спецификации.
Не подмешивать новые дома, не возвращать удалённые пользователем архивы в рабочее дерево.
Полный exporter перезаписывает весь набор: не запускать его в таком рабочем дереве
для задачи, ограниченной парковками. Проверка всех четырёх изображений проводится
через каталог и SHA/PNG; настоящие улицы проверяются с имеющимися в сохранении объектами,
без создания договоров или поддельных API-ответов ради отсутствующих состояний.

[Проверка обновления парковок](../reviews/PARKING-review.md).

## Замена рисунков без изменения правил

1. Заменить нужный файл в source/house или source/parking, сохранив имя. Для остальных объектов — source/.
2. При изменении viewBox/холста/основания скорректировать scripts/sprite-spec.json:
   sourceFile, размеры, anchorX/Y, worldPerSourcePixel, pixelRatio.
3. Из корня репозитория в WSL выполнить:

```sh
node scripts/export-sprites.mjs
docker compose -p vsk-pitch --env-file infra/pitch.env.example -f infra/pitch.compose.yaml build frontend
docker compose -p vsk-pitch --env-file infra/pitch.env.example -f infra/pitch.compose.yaml up -d --no-deps frontend
```

Экспорт использует Playwright/Chromium из tests/pitch-browser. Он проверяет точные 35 ID
и группы, локальные ссылки и размеры, растрирует SVG, обрезает прозрачные поля,
пересчитывает anchor, записывает PNG/manifest/catalog. Входные SVG не меняются.
Манифест содержит SHA-256 PNG и исходников; URL изображений версионируется по хешу.
Внешние изображения/скрипты не допускаются; ограниченный встроенный PNG поддержан для
совместимости и текущего пользовательского набора домов.
После обновления нужен Ctrl+F5 в уже открытой вкладке.

Для обычной замены рисунков backend/БД не нужны. Смена числа ступеней или порогов —
изменение правил с проверкой backend и согласованным обновлением обоих приложений;
пересоздание PostgreSQL/Redis, удаление volumes или reset не требуются.
«Под снос» обозначается тонировкой и накладкой, без дополнительных копий домов.
