# Требования к модулям

Согласованных SRS пока нет. Подготовлены проекты по [шаблону](../templates/SRS.md):

| Документ | Объём | Статус |
| --- | --- | --- |
| [SRS-ENGINE](SRS-ENGINE.md) | Расчёт, состояния, инварианты, внутренние операции и проверочные сценарии | Проект; игровые правила подтверждены, технические порядки требуют решения |
| [SRS-STORAGE](SRS-STORAGE.md) | Сохранение, журнал, атомарность, повторы, конкуренция, снос и восстановление | Проект требований, не готовая SQL-схема или миграция |

Начальная рамка — [проект границ корпоративного MVP](../MVP-SCOPE.md).
Контракт договоров/оргданных отложен пользователем до появления сведений об источнике.
Это не блокирует документацию внутренних расчётов и хранения; подключение реальных данных
остаётся отдельной зависимостью. Внутренние ссылки/операции SRS не являются внешним контрактом.
Наличие scope не означает согласования SRS или доступности полей реального источника.

Исходный актуальный объём задают [принятые игровые правила](../GAME-RULES.md) и
[концепция v0.4](../concept/Insurance_City_Concept_Architecture_v0.4.md), не историческая v0.3.
Неизвестные поля источника, маппинг и нагрузки нельзя превращать в согласованные требования.

Предполагаемые области: игровой расчёт, генерация карты, сцены/API,
клиентская навигация и рендер, приём продаж, идентичность и раскрытие данных.
Имена файлов: `SRS-<module>.md`. Каждое требование должно иметь проверяемый критерий.
