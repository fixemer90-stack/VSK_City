# Архитектура

Целевая архитектура описана в разделах 10–12
[концепции v0.4](../concept/Insurance_City_Concept_Architecture_v0.4.md).
Игровой расчёт задают [принятые правила](../GAME-RULES.md).
Это ещё не реализованная система.
Обязательные ограничения развёртывания: [CR-01–CR-05](CORPORATE-REQUIREMENTS.md).

## Планируемые границы

- Frontend: Angular — оболочка и навигация; PixiJS — актуальные изометрические сцены.
- Backend: приём событий, расчёт игрового состояния, генератор карты, REST API/BFF.
- PostgreSQL — источник истины; Redis входит в корпоративный стек как восстанавливаемый кеш.
- Backend поставляется отдельным Docker-образом, настраивается через env; экземпляры stateless.
- Мир, идемпотентность и сроки сноса сохраняются в PostgreSQL, не в памяти конкретной реплики.
- Постоянное хранение файлов, если потребуется, — S3/MinIO, не диск контейнера.
- Kafka — корпоративный транспорт продаж; Keycloak — идентичность и роли.
- Повтор факта не дублирует результат; сложные анимации и их исторический replay не обязательны.
- Распределение опыта сохраняется: итоговые суммы договоров не определяют вид домов без истории.
- Привязка зачёта договора к исходной улице нужна для терминаций после перевода агента.
- Улицы напрямую относятся к городам; игровых районов, их сцен и API нет.
  Кварталы — геометрия планировки, каналы — служебная оргструктура для прав.
- Смена канала в том же городе сохраняет улицу; перевод в другой филиал-город создаёт новую,
  сохраняя старую застройку на прежнем месте.
- API фильтрует имена/названия и персонализированные ответы; области прав нельзя смешивать в кеше.

Вначале — единая backend-кодовая база с логическими модулями, без обязательного
разбиения на микросервисы. Конкретные проекты, версии, схема данных и контракты ещё не созданы.

Архитектурные решения оформляются ADR по [шаблону](../templates/ADR.md)
и сохраняются в этом каталоге с именем `ADR-NNN-краткое-название.md`.
