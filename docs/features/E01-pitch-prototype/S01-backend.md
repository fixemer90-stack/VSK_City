# S01 — Backend и сохранённый демо-мир

Статус: Готово для локального синтетического питча.

Контракт: [E01](FEATURE.md). Объём файлов: src/backend/, tests/backend/, infra/pitch.compose.yaml.

## Критерии приёмки

- [x] Ядро следует правилам имущества, XP, парковок, моторных расторжений и отложенного сноса.
- [x] Существующие CSV дают 25 городов, 50 агентов в каждом, детерминированный начальный мир.
- [x] API соответствует FEATURE.md, фильтрует имена и защищает повторы requestId.
- [x] PostgreSQL хранит мир и сроки; Redis подключается реально и не является источником истины.
- [x] Backend собирается отдельным Docker-образом, настройки env, изолированный Compose.
- [x] Тесты ядра реально выполнены; рестарт и API интеграцию подтверждает S03.

Статус изменяется только после фактического выполнения проверок.

Историческая приёмка исходного E01: 17 C# assertions, 10 реальных HTTP/runtime проверок и независимое backend-ревью.
Образы запущены в vsk-pitch; команды и ограничения — в src/backend/README.md.

Обновление шкалы: 10 ступеней по `round(i × 100 / 9)`, от 1 до 25 этажей при прежнем
лимите 100 XP. Отдельный безопасный Docker console gate дал RED по прежней этажности,
затем GREEN: 18 проверок, все XP 0…100, понижение через каждый порог и legacy JSON
без изменения XP/ID/участков/сроков/receipts. Redis хранит только версию, не проекции,
поэтому смена namespace не нужна. Работающий стек этим gate не изменяется;
HTTP/persistence и развёртывание новой шкалы в эту проверку не входят.
