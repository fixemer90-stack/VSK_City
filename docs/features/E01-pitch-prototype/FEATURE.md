# E01 — Интерактивный прототип для питча

Статус: Готово для локального синтетического питча. Не корпоративный MVP и не готовая интеграция.

## Цель

Показать живую связь «продажа → изменение города» на вымышленных данных:
карта России → город → улица, дома, моторное развитие, парковки и отложенный снос.
Это не презентация из неподвижных картинок. Переходы и сценарии должны работать.

## Объём

- Angular + TypeScript + PixiJS, desktop, русские подписи, минималистичный интерфейс.
- 25 тестовых городов и 50 агентов в каждом из существующего initial-снимка.
- Отдельный ASP.NET Core backend-образ, PostgreSQL для сохранённого мира,
  Redis для восстанавливаемых технических данных; настройки через env.
- Один изолированный Compose-проект `vsk-pitch`, только синтетическая БД и собственные volumes.
  Порты для локального показа: frontend 127.0.0.1:5188, backend 127.0.0.1:5189.
- Добавление имущества/мотора, расторжение имущества/мотора, демонстрационный перевод часов
  вперёд на сутки, явный сброс исключительно тестового мира.
- Имущество: один дом; мотор: один XP, 10 ступеней 0/11/22/33/44/56/67/78/89/100,
  этажность 1/3/4/5/6/9/12/14/17/25. Порог — округление `i × 100 / 9`
  до ближайшего целого, `i = 0…9`; предел 100 XP на дом не меняется.
  Числовые XP/уровни не показываются в UI.
- Новый опыт идёт активному дому с минимумом XP; при его отсутствии/исчерпанной
  вместимости — парковки по 10 мест. Новый дом переносит доступный парковочный вклад.
- Имущественное расторжение выбирает активный дом с минимумом XP и помечает «Под снос»
  на 24 часа от первой успешной обработки. Он занимает участок и сохраняет XP,
  но не получает новый. При сносе оставшийся XP перераспределяется активным домам,
  избыток — в парковки. Таймер сохраняется в PostgreSQL и не сбрасывается при рестарте.
- Моторное расторжение сначала снимает место, иначе XP наиболее развитого дома,
  в том числе помеченного; не сносит дом. Выбор при равенстве стабилен по ID.
- Последующие имущественные расторжения не выбирают уже помеченный дом.
  Это техническое правило предотвращает назначение нескольких сносов одному объекту.
- Демонстрация ролей: агент видит только своё персональное название; директор —
  названия своего города. Фильтрация серверная. Явно обозначенный выбор демо-персоны
  не является корпоративной аутентификацией.

## Не входит

Kafka/корпоративный источник, Keycloak/реальная аутентификация, рабочий маппинг продуктов,
боевые пользователи, полный импорт исправлений/переводов, графика художника,
промышленное нормализованное хранение, нагрузочная приёмка и production-развёртывание.
Файловых загрузок/экспортов нет, поэтому S3/MinIO пока не требуется.
Минимальное demo-хранение может использовать один транзакционно блокируемый JSON-снимок
в PostgreSQL: это намеренное ограничение прототипа, не целевая промышленная схема.

## Общий интерфейс между frontend и backend

Поля JSON camelCase, даты ISO 8601 UTC. Для локального браузера запросы идут на `/api/demo`.
`rulesVersion` — версия правил проекции, независимая от сохранённой `version` мира.
При её изменении клиент не переиспользует прежний массив cities, даже если операций в мире не было.

`GET /api/demo/state?agentId=TEST-AGENT-001-044&role=agent`

```json
{
  "mode": "pitch",
  "rulesVersion": 2,
  "version": 1,
  "now": "2026-11-05T12:00:00Z",
  "viewer": {
    "agentId": "TEST-AGENT-001-044",
    "streetId": "STREET-TEST-AGENT-001-044",
    "cityId": "TEST-CITY-001",
    "firstName": "Михаил",
    "lastName": "Волков",
    "role": "agent"
  },
  "cities": [
    {
      "id": "TEST-CITY-001",
      "name": "Москва",
      "mapX": 19,
      "mapY": 59,
      "streets": [
        {
          "id": "STREET-TEST-AGENT-001-044",
          "agentId": "TEST-AGENT-001-044",
          "name": "Улица Михаила Волкова",
          "scenario": "overflow",
          "houses": [
            { "id": "HOUSE-001", "lotIndex": 0, "xp": 100, "tier": 10,
              "floors": 25, "status": "active", "demolishAt": null }
          ],
          "parking": [ { "id": "PARK-001", "lotIndex": 1, "spaces": 10 } ]
        }
      ]
    }
  ]
}
```

Пример сокращён и иллюстративен, не фактический ответ сервера. На практике выдаётся весь
демо-мир, названия чужих улиц равны null. Имя/фамилия есть только у выбранного viewer;
не выдавать скрытые имена в дополнительных полях улиц. mapX/mapY — позиции 0..100 на
стилизованной схеме, не геодезические координаты. В городском обзоре допустим LOD,
на детальной улице должны оставаться доступны все её дома, без агрегирования договоров.

`POST /api/demo/actions?agentId=<viewer>&role=agent|director`

```json
{ "agentId": "TEST-AGENT-001-044", "type": "property", "requestId": "demo-unique-key" }
```

`type`: property / motor / terminate-property / terminate-motor / advance-day / reset.
Ответ — полный State того же формата. Повтор requestId не изменяет мир второй раз.
advance-day двигает только сохранённое demo-смещение времени; reset явно сбрасывает
только тестовый мир и требует подтверждения в UI. Обычные GET не сбрасывают мир.
Ошибки — JSON с message и HTTP 400/404/409; ошибки подключения не маскируются успехом.
`GET /health` проверяет реальные PostgreSQL и Redis. Интеграционные реквизиты — env.

## Совместимость сохранённого мира при смене шкалы

`tier`/`floors` — производные от сохранённого `xp`, а не самостоятельный прогресс.
Десериализация прежнего JSON игнорирует записанные значения этих getter-only полей;
ответ API вычисляет их заново по новой шкале. Сброс, seed, перераспределение XP,
смена ID/lotIndex, сроков сноса, receipts, demo-смещения или world version не требуются.
Обычные наступившие сносы по-прежнему обрабатываются worker/запросом по сохранённым срокам.
Redis в E01 содержит только целую версию `pitch:world:version`, не снимки мира или
`tier`/`floors`; проекция всегда строится из PostgreSQL. Поэтому инвалидировать namespace
кеша при этой смене шкалы не требуется. HTTP-ответы имеют `Cache-Control: no-store`.

Для изменения шкалы отдельно выполнен безопасный Docker console gate: 18 C# проверок,
включая все XP 0…100, переход вниз через каждый порог и загрузку прежнего JSON
с неизменностью всех непроизводных полей. HTTP/persistence suites на используемом
оператором мире не запускались; это не новая runtime/браузерная приёмка и не развёртывание.
