# Features и Stories

## Активная разработка

| Feature | Назначение | Статус |
| --- | --- | --- |
| [E01 — Питч-прототип](E01-pitch-prototype/FEATURE.md) | Живая карта, город/улица, демонстрационные продажи и снос на вымышленных данных | Готово для локального питча |
| [E02 — Автоматические проверки](E02-continuous-integration/FEATURE.md) | Lint/types/tests/build, спрайты и отдельный CI runtime | В процессе; real Actions run ещё не подтверждён |

Корпоративная интеграция и производственный MVP не входят в E01.

Для корпоративного MVP есть [проект границ](../MVP-SCOPE.md) и проекты
[расчёта](../SRS/SRS-ENGINE.md) / [хранения](../SRS/SRS-STORAGE.md).
Внешний контракт пока отложен: это не запрещает независимую детализацию ядра,
но не разрешает подключение реальных данных. Корпоративное ядро ещё не разложено в отдельный Feature/Story-набор;
E02 относится к инфраструктуре качества и не закрывает эту разработку.
Декомпозиция должна опираться на [принятые игровые правила](../GAME-RULES.md),
[концепцию v0.4](../concept/Insurance_City_Concept_Architecture_v0.4.md) и
[дорожную карту](../ROADMAP.md). Наличие согласованных правил не закрывает ни одну Story.

Для каждой Feature создать `E01-<slug>/FEATURE.md`, а рядом — атомарные
`S01-<slug>.md`, `S02-<slug>.md` по [шаблонам](../templates/README.md).

- Одна Story — один проверяемый результат.
- До кода фиксируются границы, зависимости и критерии приёмки.
- Feature закрывается только после выполнения всех входящих Stories.
- Реализацию подтверждают команды и результаты проверок, а не наличие файлов.
- Статусы: «Не начато», «В процессе», «Готово», «Заблокировано».
- При закрытии обновлять Story, родительскую Feature и фактический статус MVP.
