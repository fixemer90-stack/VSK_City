# Проверка питч-прототипа в браузере

Python fixture-тесты проверяют входные CSV. Этот отдельный набор Playwright проверяет
реальный локальный frontend/API и сохранение состояния при рестарте backend.
Нужен запущенный изолированный Compose-проект `vsk-pitch` из E01.

Из этого каталога:

```sh
npm ci
npx playwright install chromium
npm test
```

По умолчанию base URL: `http://127.0.0.1:5188`, переопределяется PITCH_BASE_URL.
Не направлять тесты на рабочие/чужие окружения: они меняют синтетические продажи,
сбрасывают общий демо-мир, двигают демо-время и перезапускают сервис backend
только проекта `vsk-pitch`. PostgreSQL/Redis volumes не удаляются.

Проверки:

- Реальные health/seed/API, роли и серверное отсутствие чужих имён.
- Новое имущество, моторные пороги, идемпотентный повтор requestId, сохранение опыта,
  отметка «Под снос» и фактическое завершение при продвижении демо-времени.
- Реальный браузер: страна → город → улица, действия, роли и desktop-ширины.
- Отдельно маркированная искусственная HTTP 503 проверяет только error-state интерфейса;
  остальные основные сценарии используют настоящий API, без подмены ответов.
- Честное ограничение на маленьком экране вместо сломанной мобильной версии.
- Реальный рестарт backend, затем сравнение улицы/опыта/участков/срока и повтор
  уже обработанного расторжения, чтобы проверить сохранённый журнал ключей.

Скриншоты, trace при ошибках и persistence.json сохраняются в игнорируемый
`test-results/pitch` в корне репозитория; путь можно задать PITCH_TEST_OUTPUT.
Скриншоты должны быть просмотрены отдельно: отсутствие ошибок тестов не доказывает
художественное качество карты и застройки. Готовность E01 отмечается только после запуска.

## Проверка визуальных изменений без сброса мира

```sh
PITCH_TEST_OUTPUT=../../test-results/visual npx playwright test map-centers.spec.js sprites.spec.js ten-tiers.spec.js parking.spec.js
```

Эти четыре spec не создают продаж, не сбрасывают мир и не перезапускают backend.
Проверяется отсутствие исходящих записывающих запросов. Проверяются границы карты на
1100/1280/1440/1920 px, прямые клики по всем 25 точкам, hover малого города,
два уникальных центра, 35 PNG с прозрачностью и хешами источников, каталог и sprite instances,
десять равномерных порогов и стабильность вариантов A/B после reload и смены вида.
parking.spec сверяет все четыре новых исходника/PNG через HTTP и фактические parking Sprite
на существующей улице и в городе, без создания продаж ради отсутствующих состояний.
Не путать с полным `npm test`, который
также запускает пять сценариев E01, среди которых есть изменяющие мир.
