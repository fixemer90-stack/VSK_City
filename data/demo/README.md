# Вымышленные входные данные VSK City

Готовый набор: **25 городов, в каждом ровно 50 агентов** — 1 250 агентов.
В каждом полном снимке 32 950 страховых договоров: 4 175 имущественных и 28 775 моторных.
Это один и тот же портфель в двух состояниях, а не два независимых набора договоров.

Все агенты, АГД, каналы, филиальные коды, продукты и договоры вымышлены.
Названия городов реальные, но их соответствие `TEST-BR-*` не описывает действующую
структуру компании. Нет клиентов, премий, документов, телефонов, email или паролей.
Совпадение с именем реального человека случайно; идентификаторы имеют префикс `TEST-`.

Это тестовый черновик входных таблиц, не утверждённая схема корпоративного источника.
Распределение продаж специально подобрано для сценариев, а не для оценки бизнес-нагрузки.
В каждом городе одинаковый набор профилей; даты договоров различаются.
Геометрии, координат городов, готовых домов, улиц, XP и пользователей авторизации здесь нет.
Их должен создавать будущий импортёр/движок, которого пока нет.

## Файлы

В каталогах [initial](initial/manifest.json) и [terminated](terminated/manifest.json)
одинаковые таблицы CSV: UTF-8, разделитель — запятая, первая строка — имена полей.
Пустая дата обозначается пустой ячейкой. Все даты/время — ISO 8601 в UTC.

| Файл | Содержимое |
| --- | --- |
| `cities.csv` | 25 городов и их тестовые коды филиалов |
| `channels.csv` | 75 служебных каналов, по 3 на филиал; не игровые районы |
| `agents.csv` | 1 250 агентов, номера АГД, имена и текущая оргпринадлежность |
| `products.csv` | 2 тестовых продукта и их исключительно демонстрационный маппинг |
| `contracts.csv` | Полный портфель из 32 950 договоров с текущими статусами |
| `scenarios.csv` | Подсказка тестировщику: номер АГД → сценарий; не входное бизнес-поле |
| `manifest.json` | Признак synthetic, версия черновика, дата снимка и точные количества |

Поля договоров:

- `contractId`, `contractNumber` — уникальные ID и номер страхового договора.
- `agencyAgreementNumber` — связь с агентом по номеру АГД.
- `productCode` — связь с тестовым продуктом; в реальном источнике возможен другой ID/название.
- `concludedAt` — дата заключения.
- `status` — `active` / `terminated` («активен» / «досрочно расторгнут»).
- `terminatedAt` — дата досрочного расторжения; пусто у активного договора.
- `sourceUpdatedAt`, `sourceVersion` — вымышленные служебные поля для проверки обновлений.

Доступность последних полей и формат остальных ещё предстоит проверить на источнике.
У договора **нет филиала**. Его связь с городом определяется через агента и улицу зачёта.
У агента `agentId` — дополнительный тестовый ключ, не обещание такого поля в источнике;
`branchId` и `channelId` ссылаются на справочники, номер АГД уникален.
Связь АГД с корпоративной авторизацией в этих данных не моделируется.
Поле `demoCategory` из products.csv — только тестовый маппинг, не производственное правило.

## Покрываемые профили

| Сценарий | Агентов во всём наборе | Состав портфеля одного агента до расторжений |
| --- | --- | --- |
| `empty` | 125 | Без договоров; нужна пустая улица |
| `motor_only` | 250 | Только 13 моторов; парковки |
| `property_only` | 250 | 4 имущественных, без моторов |
| `mixed` | 250 | 5 имущественных, 23 мотора |
| `developed` | 125 | 2 имущественных, 40 моторов |
| `skyscraper` | 75 | 1 имущественный, 100 моторов |
| `overflow` | 25 | 1 имущественный, 123 мотора; избыток в парковках |
| `large` | 25 | 50 имущественных, 120 моторов |
| `property_termination` | 75 | 3 имущественных, 8 моторов; затем расторжение одного имущественного |
| `motor_termination` | 50 | 2 имущественных, 12 моторов; затем расторжение одного моторного |

Внутри каждой улицы имущество заключено раньше моторов. Для воспроизводимого начального
демо-импорта можно сортировать договоры по `concludedAt`, затем `contractId`.
Это порядок тестового воспроизведения, не согласованная политика поздних фактов источника.

## Два полных снимка и сценарий «Под снос»

1. `initial`: состояние на 3 ноября 2026, 09:00 UTC. Все договоры активны.
2. `terminated`: состояние на 5 ноября 2026, 09:00 UTC. Те же ID и номера договоров;
   75 имущественных и 50 моторных теперь расторгнуты, их sourceVersion изменена с 1 на 2.
   Дата расторжения в источнике — 4 ноября 2026, 12:00 UTC.
3. После импорта initial применить terminated. В тесте задать серверное время первой
   успешной обработки расторжений: 5 ноября 2026, 09:00 UTC.
4. Ожидаемое будущее поведение: 75 домов получают отметку «Под снос», сохраняют опыт
   и занимают участки, но больше не получают новый опыт. Моторные расторжения не сносят дома.
5. Повторно импортировать тот же terminated: нет второго списания, срок сноса не меняется.
6. На границе 6 ноября 2026, 09:00 UTC должны удалиться помеченные дома;
   их оставшийся моторный опыт перераспределяется, избыток становится парковками,
   участки освобождаются. Срок привязан к успешной обработке в игре, не к terminatedAt
   и не автоматически к snapshotAt. При другом времени первого импорта срок будет другим.

Эти шаги описывают принятые в обсуждении ожидания, **не выполненный тест движка**.
Генератор проверяет только входные данные. Новые договорённости о 24 часах пока
не синхронизированы с разделом терминации в [GAME-RULES](../../docs/GAME-RULES.md).
Не нужно превращать отсутствие строки в снимке в расторжение или пересоздавать весь мир:
при повторных загрузках сохраняются распределение опыта, улица первоначального зачёта и таймеры.
Обычное истечение не должно убирать договор из охвата полной выгрузки или снимать игровой вклад.
Демо-«дата 0» — 1 января 2026, 00:00 UTC; это не выбранная дата запуска продукта.

## Воспроизведение

Из корня репозитория, Python 3.11+; сторонних Python-зависимостей нет:

```sh
python3 scripts/generate_demo_data.py --cities 25 --phase initial --output data/demo/initial --overwrite
python3 scripts/generate_demo_data.py --cities 25 --phase terminated --output data/demo/terminated --overwrite
python3 -m unittest discover -s tests -p 'test_demo_data.py' -v
```

Для другого размера укажите `--cities` от 20 до 30 и отдельный каталог `--output`.
В каждом городе всегда 50 агентов. Без `--overwrite` существующие файлы набора
не перезаписываются. С этим флагом заменяются только шесть именованных CSV и manifest.json,
другие файлы не удаляются. Команда не обращается к сети, БД, API или учётным записям.
Два запуска с одинаковыми аргументами дают побайтно одинаковые файлы.
